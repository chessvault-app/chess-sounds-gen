# chess-sounds-gen

A chess UI sound set, synthesized from scratch — 15 sounds plus 16
round-robin variations of the board sounds, in the character of the Lichess
standard set. No recordings or samples are used or shipped: everything in
`out/` is generated by `synth_chess_sounds.py` (Python stdlib only, no
dependencies).

Ready-to-use audio lives in `out/wav`, `out/ogg` and `out/mp3`. Open
`preview.html` in a browser to audition the whole set — the audio is
embedded in the page, so it works straight from a clone.

There is deliberately **no check sound**: like Lichess's standard theme
(whose `Check.mp3` is a symlink to `Silence.mp3`), a checking move just plays
the normal move/capture sound.

## How it stays close to the originals

The Lichess standard sounds are **non-free** (listed under "Exceptions
(non-free)" in lila's `COPYING.md`), so they can't be reused directly.
Instead, `tools/modal_fit.py` *measures* them — per frequency band (10 bands,
80 Hz–16 kHz): the RMS envelope curve on a 1–2 ms grid (fine grids in the
mids/highs keep the attack snappy; tail noise floor subtracted), the band's
tonality (spectral peak-to-median ratio), and up to four spectral peak
frequencies. Double-hit sounds (capture) are segmented and measured per hit.

Those measured numbers live in `fitted_params.py`. The synthesizer rebuilds
each band as *(sine peaks + noise, mixed by measured tonality) × measured
envelope curve* — a vocoder-style resynthesis that reproduces the reference's
time-frequency envelope by construction. Band-envelope verification
(`tools/verify.py`) puts the synthesized board sounds within ~3–6 dB median
of the references. Imitating a sound recording with independently generated
audio is explicitly permitted (17 U.S.C. §114(b)); measured frequencies and
envelope values are unprotectable facts.

The melodic cues (game start/end/win/lose/draw, promote) are deliberately
**original compositions** — Lichess has no jingles to match, and copying
e.g. Chess.com's tunes would infringe composition rights.

## The sounds

`out/wav/*.wav` — 44.1 kHz / 16-bit / mono; the same sounds in `out/ogg/`
and `out/mp3/`.

| file | event | source of character |
|---|---|---|
| `move-self` | you move | measured (Lichess Move) |
| `move-opponent` | opponent moves | same, pitched −4 % |
| `capture` | capture | measured (Capture, both hits) |
| `castle` | castling | two move-knocks, 110 ms apart |
| `promote` | promotion | original ascending sparkle |
| `premove` | premove set | select tick, pitched down, quiet |
| `select` | piece pick-up | measured (Select) |
| `illegal` | illegal move | measured (Error) |
| `notify` | draw offer / generic | measured (GenericNotify) |
| `game-start` | game begins | original two rising chimes |
| `game-end` | game over | original resolving motif |
| `game-win` | win | original arpeggio + chord |
| `game-lose` | loss | original descending line |
| `game-draw` | draw | original two equal chimes |
| `low-time` | clock low | measured (LowTime) |

Output peak levels of the measured sounds match the reference files
(e.g. move −0.2 dBFS, low-time −7.4 dBFS).

### Round-robin variations

`move-self-1..4`, `move-opponent-1..4` and `capture-1..8` are variations of
the corresponding base sound — pitch shift, a spectral tilt (crisper/duller),
envelope time-stretch (which also varies capture's double-hit rhythm), and a
different noise/phase "take". Play them in rotation (or pick one at random
per move) so repeated moves don't sound like a single sample.
`capture-5..8` deliberately explore the higher/snappier direction (up to
+10 % pitch, strong brightness tilt, tighter timing) — if one of them is
"the" capture for you, swap it in as the base. They're defined in the
`VARIANTS` table; the knobs are
`resynth(..., pitch=, bright=, stretch=, rng=)`.

## Regenerate / tweak

```sh
python3 synth_chess_sounds.py     # stdlib only, no dependencies
```

This rewrites `out/wav/`, `preview.html`, and — if `ffmpeg` is on PATH —
`out/ogg/` and `out/mp3/`. It's deterministic (fixed seed), so rerunning
without edits reproduces identical files. Knobs:

- per-sound volume: the `SOUNDS` table (measured sounds use `ref_gain()`)
- the jingles: the `s_game_*()` and `s_promote()` builders
- the variations: the `VARIANTS` table
- everything measured: regenerate `fitted_params.py` (below)

## Re-measuring the references (optional)

The reference files are not included (non-free) and are gitignored. To redo
the analysis:

```sh
mkdir -p ref && cd ref
B=https://raw.githubusercontent.com/lichess-org/lila/master/public/sound/standard
for f in Move Capture Error GenericNotify LowTime Select; do
  curl -sLO "$B/$f.mp3" && ffmpeg -y -i "$f.mp3" -ar 44100 -ac 1 "$f.wav"
done
cd .. && python3 tools/modal_fit.py     # rewrites fitted_params.py
python3 synth_chess_sounds.py
python3 tools/verify.py                 # band-envelope diff vs references
```

`tools/analyze.py <wav...>` prints a quick fingerprint (decay times,
spectral peaks) of any short sound.
